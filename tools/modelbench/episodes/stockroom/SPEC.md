# stockroom

A small spare-parts warehouse: items, the stock book, customer orders, supplier terms,
shipping, and the reports the office prints. Python 3, standard library only.

Mass is stored in **grams**, length in **millimetres**, and money in **integer cents** at
every stage. Floating point is not used anywhere in the money path.

## Layout

The modules were just grouped by role. The left column is where a module used to live, the
right column is where it lives now; `moves.json` carries the same table for a script.

| Old module | New module |
|-----------------|---------------------------|
| `stockroom.units` | `stockroom.core.units` |
| `stockroom.money` | `stockroom.core.money` |
| `stockroom.paths` | `stockroom.config.paths` |
| `stockroom.settings` | `stockroom.config.settings` |
| `stockroom.orders` | `stockroom.domain.orders` |
| `stockroom.stock` | `stockroom.domain.stock` |
| `stockroom.suppliers` | `stockroom.domain.suppliers` |
| `stockroom.shipping` | `stockroom.domain.shipping` |
| `stockroom.daily` | `stockroom.reporting.daily` |
| `stockroom.monthly` | `stockroom.reporting.monthly` |
| `stockroom.formats` | `stockroom.reporting.formats` |
| `stockroom.csvio` | `stockroom.io.csvio` |
| `stockroom.jsonio` | `stockroom.io.jsonio` |

**`stockroom.items` and `stockroom.problems` did not move.** Other projects import them at
those paths, and they stay at the top level of the package.

## Rules

1. **Imports are absolute.** `from stockroom.<package> import <module>`, then use
	`<module>.<name>`. No relative imports.
2. **The old module paths are gone.** Do not recreate them under any form, and do not add
	alias or compatibility modules. A module that re-exports from the new home hides a stale
	reference instead of fixing it.
3. **The module grouping is the move; it is not an invitation to rename anything.** The
	module names, class names, function names and their signatures are unchanged.
4. **`stockroom/data/` is generated by the supplier's export.** It is read, never edited.
5. `check.py` is the project's deterministic check; `moves.json` is the machine-readable
	move list. Neither is edited as part of the work.

## What the project does, in one line per module

- `core.units` — grams/kilograms and millimetres/centimetres, integer arithmetic.
- `core.money` — multiply, percentage with half-up rounding, and cents formatting.
- `config.paths` — the data directory, resolved from the module's own location.
- `config.settings` — the default currency and tax rate, and the two data-file names.
- `items` — `StockItem`, with its mass in kilograms and its value in cents.
- `problems` — the exception hierarchy.
- `domain.orders` — `Order`, its subtotal, its taxed total, its weight and its unit count.
- `domain.stock` — the book of `(item, quantity)` pairs, keyed by SKU.
- `domain.suppliers` — supplier terms and the amount payable after the discount.
- `domain.shipping` — the flat base plus per-kilogram and per-kilometre charges.
- `reporting.formats` — the two line formats the reports print.
- `reporting.daily` — the day's summary, and the reorder list.
- `reporting.monthly` — a month of daily summaries rolled into one figure.
- `io.csvio` — reading the supplier's CSV export and writing the book back out.
- `io.jsonio` — the JSON export the reporting service reads.
- `cli` — the command line the warehouse staff use.
