## Blocking Issues (must fix)

### 1. Orchestrator function not first — violates `style/common.md`

**Location:** `taskview/taskview.py` — `main()` at line 239; first function is `parse_args()` at line 24.

**Rule:** `style/common.md` § "Maps" — "A file that is not trivially readable at a glance opens with either an orchestrator function that calls well-named helpers, or a short header map of its own structure."

### 2. `compute_metrics` return shape undocumented — violates `style/common.md`

**Location:** Line 76-129

**Rule:** `style/common.md` § "Document non-obvious returns" — "Say what a function returns when that isn't obvious from the code... One line."

The function returns a dict with specific keys (`done_day`, `done_week`, `done_month`, `active`, `this_week`, `this_month`, `later`, `open_tasks`). Callers (`build_view`) depend on this exact shape. Add a docstring or `TypedDict`.

---

### 3. `inotify` fallback catches too narrowly — correctness risk

**Location:** Line 257

```python
except (OSError, PermissionError):
    watch_poll(args.csv, render)
```

If `inotify.adapters.Inotify()` succeeds at import but `add_watch()` or `event_gen()` fails for any other reason (e.g., filesystem doesn't support inotify, permission on parent dir, resource exhaustion), the exception propagates and crashes the watch loop instead of falling back to polling.

**Fix:** Catch `Exception` (or `BaseException` excluding `KeyboardInterrupt`/`SystemExit`) so any inotify failure triggers the polling fallback.
